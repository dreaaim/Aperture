# Aperture项目结构优化计划

## 1. 项目结构重构

### 1.1 目录结构优化
- 创建清晰的分层目录结构，包括：
  - `app/api` - API层，处理HTTP请求和响应
  - `app/services` - 业务服务层，实现核心业务逻辑
  - `app/models` - 数据模型层，定义数据结构
  - `app/repositories` - 数据访问层，处理数据存储和检索
  - `app/config` - 配置管理，集中处理配置相关逻辑
  - `app/utils` - 工具函数，提供通用功能

### 1.2 模块职责分离
- 将`router.py`拆分为：
  - `app/services/intent_service.py` - 意图分类服务
  - `app/services/model_service.py` - 模型管理和选择服务
- 将`cache.py`拆分为：
  - `app/services/cache_service.py` - 缓存业务逻辑
  - `app/utils/embedding.py` - 文本嵌入工具
- 将`storage.py`拆分为：
  - `app/repositories/memory_repository.py` - 内存存储实现
  - `app/utils/math.py` - 数学工具函数

## 2. 代码解耦与抽象

### 2.1 引入服务层抽象
- 为核心服务创建抽象接口，如：
  - `IntentService` - 意图分类服务接口
  - `ModelService` - 模型管理服务接口
  - `CacheService` - 缓存服务接口
  - `Repository` - 数据存储接口

### 2.2 依赖注入优化
- 实现简单的依赖注入机制，提高代码可测试性
- 在`main.py`中集中管理依赖注入

### 2.3 配置管理优化
- 将硬编码的配置（如模型目录、意图关键词）移至配置文件
- 提供环境变量覆盖配置的能力

## 3. 代码复用与标准化

### 3.1 工具函数标准化
- 提取通用工具函数到`app/utils`目录
- 为工具函数添加类型提示和文档

### 3.2 错误处理标准化
- 实现统一的错误处理机制
- 为API添加适当的异常处理

### 3.3 日志记录标准化
- 添加结构化日志记录
- 为不同层级的代码添加适当的日志级别

## 4. 测试与验证

### 4.1 测试结构优化
- 为每个模块创建对应的测试文件
- 实现单元测试和集成测试

### 4.2 代码质量验证
- 运行类型检查和代码风格检查
- 确保所有测试通过

## 5. 实施步骤

1. **准备阶段**：创建新的目录结构，保留原有文件作为备份
2. **重构阶段**：按照分层结构逐步迁移和重构代码
3. **验证阶段**：运行测试和类型检查，确保功能正常
4. **清理阶段**：移除临时文件和备份，完成最终优化

## 预期收益

- 代码层次更加清晰，易于理解和维护
- 模块间耦合度降低，提高代码可测试性
- 功能复用性增强，减少代码冗余
- 配置管理更加灵活，便于环境切换
- 整体项目结构更加标准化，符合现代Python项目最佳实践
