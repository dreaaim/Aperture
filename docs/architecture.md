# 架构文档

## 系统架构概览

Aperture 采用模块化设计，将不同功能组件分离为独立模块，便于维护和扩展。系统由 API 层、服务层、核心逻辑层和存储层组成，各层职责明确，通过依赖注入实现松耦合。

## 核心模块说明

### API 层

API 层负责处理 HTTP 请求，提供 RESTful 接口，是系统与外部交互的入口点。

#### `app/api/endpoints.py`
- 定义 API 路由，主要是 `/v1/query` 端点
- 处理请求参数验证和响应格式化
- 协调各服务组件完成请求处理
- 记录请求和响应日志

#### `app/api/middleware.py`
- 实现全局错误处理中间件
- 统一错误响应格式
- 捕获和记录异常

### 服务层

服务层封装了核心业务逻辑，为 API 层提供服务支持。

#### `app/services/cache_service.py`
- 提供语义缓存相关服务
- 实现文本嵌入生成
- 管理缓存条目
- 实现基于 Cross-Encoder 的重排序机制，提高缓存匹配准确性

#### `app/services/intent_service.py`
- 提供意图分类服务
- 实现基于关键词的意图识别

#### `app/services/model_service.py`
- 提供模型管理和选择服务
- 实现模型评分和选择算法

#### `app/services/container.py`
- 依赖注入容器
- 管理服务实例的创建和生命周期

#### `app/services/model_adapters/`
- **base_adapter.py**：基础适配器类，定义统一接口
- **claude_adapter.py**：Claude 模型适配器，处理 Claude API 格式
- **openai_adapter.py**：OpenAI 模型适配器，处理 OpenAI API 格式
- 实现请求格式化和响应解析
- 支持格式转换和错误处理
- 提供统一的模型调用接口

### 核心逻辑层

核心逻辑层实现了系统的核心功能，包括路由决策、缓存管理等。

#### `app/router.py`
- 实现路由决策逻辑
- 提供意图分类和难度估计功能
- 实现模型选择算法
- 管理模型目录

#### `app/cache.py`
- 实现语义缓存机制
- 提供文本嵌入生成功能
- 实现相似性搜索算法

#### `app/models.py`
- 定义数据模型
- 实现请求和响应的数据结构
- 定义模型状态和缓存条目结构

#### `app/config.py`
- 管理应用配置
- 定义系统参数和阈值
- 提供配置访问接口

### 存储层

存储层负责数据的持久化和管理，为系统提供数据支持。

#### `app/storage.py`
- 实现内存存储
- 管理缓存条目和请求日志
- 提供数据访问接口

#### `app/repositories/memory_repository.py`
- 实现内存数据仓库
- 提供请求ID生成和日志管理功能

## 各模块职责

### `app/main.py`
- **职责**：FastAPI 应用入口
- **功能**：
  - 创建和配置 FastAPI 应用实例
  - 添加中间件
  - 包含 API 路由
  - 设置启动和关闭事件

### `app/api/endpoints.py`
- **职责**：API 端点实现
- **功能**：
  - 定义 `/v1/query` 端点
  - 处理请求参数验证
  - 协调服务组件完成请求处理
  - 格式化响应

### `app/services/container.py`
- **职责**：依赖注入容器
- **功能**：
  - 管理服务实例的创建
  - 提供服务访问接口
  - 实现依赖注入

### `app/router.py`
- **职责**：路由逻辑
- **功能**：
  - 意图分类
  - 难度估计
  - 模型选择
  - 模型目录管理

### `app/cache.py`
- **职责**：语义缓存
- **功能**：
  - 文本嵌入生成
  - 相似性搜索
  - 缓存条目管理

### `app/models.py`
- **职责**：数据模型定义
- **功能**：
  - 定义请求和响应模型
  - 定义模型状态和缓存条目结构
  - 实现数据验证

### `app/storage.py`
- **职责**：存储管理
- **功能**：
  - 内存存储实现
  - 缓存条目管理
  - 请求日志管理

### `app/repositories/memory_repository.py`
- **职责**：数据仓库
- **功能**：
  - 请求ID生成
  - 日志管理
  - 数据持久化

### `app/services/model_adapters/`
- **职责**：模型适配器
- **功能**：
  - 处理不同API格式的模型请求
  - 提供统一的模型调用接口
  - 实现请求格式化和响应解析
  - 支持错误处理和重试机制

## 配置管理

系统配置通过 `app/config/settings.py` 管理，主要配置项包括：

- **嵌入维度**：`embedding_dim`，定义文本嵌入向量的维度
- **缓存阈值**：
  - `direct_hit`：直接命中的相似度阈值
  - `few_shot`：少样本学习的相似度阈值
- **路由权重**：
  - `history`：历史性能权重
  - `price`：价格权重
  - `quota`：配额权重
  - `difficulty_match`：难度匹配权重

## 扩展点

Aperture 设计了多个扩展点，便于开发者根据需要进行定制：

1. **嵌入模型**：替换 `embed_text` 函数，使用真实的嵌入模型
2. **向量数据库**：集成真实的向量数据库，替代内存存储
3. **模型网关**：集成 LiteLLM、LangChain 等模型网关
4. **意图分类**：实现更复杂的意图分类算法
5. **模型选择**：自定义模型选择策略

## 技术决策

1. **内存存储**：使用内存存储简化原型实现，便于快速开发和测试
2. **基于关键词的意图分类**：使用简单的关键词匹配实现意图分类，适合原型阶段
3. **确定性嵌入**：使用基于哈希的确定性嵌入，避免外部依赖
4. **模块化设计**：采用清晰的模块化设计，便于后续扩展和维护
5. **依赖注入**：使用依赖注入模式，提高代码可测试性和可维护性
6. **重排序机制**：使用 Cross-Encoder 模型对缓存检索结果进行重排序，提高缓存匹配准确性，减少幻觉
